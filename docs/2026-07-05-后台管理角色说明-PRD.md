## 文档目的

本文档用于说明后台管理系统中**有哪些管理角色**、**每个角色能做什么**、**数据可见范围如何隔离**，供秘书处、开发、测试和运维在账号分配、权限配置、验收测试时统一参照。

> **范围说明**：本文只描述**后台管理端**角色。前台用户的「会员 / 非会员 / 有效会员」属于业务身份，不是后台管理角色，见 §八。

## 一、角色总览

后台管理侧共 **4 类业务角色 + 1 类系统角色**：

| # | 角色名称 | 建议账号数 | RuoYi 角色 Key（建议） | 数据范围 | 主要使用人 |
|---|---------|-----------|----------------------|---------|-----------|
| 1 | 超级管理员 | 1 | `admin` | 全系统 | 技术运维 |
| 2 | 学会总管理员（秘书处） | 2–3 | `paleo_admin` | 12 个学会（1 总学会 + 11 分会） | 秘书处老师 |
| 3 | 分会管理员 | 11（首期每分会 1 个） | `paleo_branch_{code}` | 仅绑定的 1 个分会 | 各分会负责人 |
| 4 | 财务审核员 | 1–2 | `paleo_finance` | 全站缴费/发票（菜单受限） | 财务或秘书处代操作 |

### 需求来源摘要

- **0617 客户原话**：「各分会管理员账号和密码只能单独进入对应分会，不能进入其他学会内容，不能修改其他学会内容。秘书处的总管理员账号均可以进入每一个学会。然而每个分会负责人只有 1 个对应的分会管理员账号。」
- **0625 客户原话**：总学会在「数据统计」和「学会/分会管理」中需与 11 个分会**独立拆分**，总学会有独立收支，不与分会混计。
- **0626 客户确认**：退会后再入会**无需**管理员解锁；CMS 内容**管理员直接发布**，无多人审批流。
- **入会审核权演变**：0601 原需求为「分会负责人审查通过本分会会员」→ 0612 统一会员体系，会员费只收一次 → 0617 引入入会/退会申请书机制，审核集中到秘书处总管理员。分会管理员默认不参与入会/退会审核，但可通过分配 `paleo:membership:review` 权限开放。

### 术语说明

> **「学会管理员」在不同需求文档中的指代**：0617、0625 等需求文档中使用「学会管理员」一词，在不同上下文中有不同含义。涉及入会/退会审核时指**学会总管理员（秘书处）**；涉及上传盖章通知 PDF、摘要模板时指**对应会议的发布者**（总管理员或分会管理员均可）。本文档使用「学会总管理员」「分会管理员」等精确角色名称，避免歧义。

### 架构关系

```
超级管理员 ──────────────► 全系统（含 RuoYi 框架配置）
学会总管理员 ────────────► 全平台汇总 + 总学会 + 11 分会
分会管理员（×11） ───────► 仅本分会（paleo_admin_association 绑定）
财务审核员 ──────────────► 全站缴费数据（仅审核/统计菜单）
```

## 二、角色详细说明

### 2.1 超级管理员

| 属性 | 说明 |
|---|---|
| 角色标识 | `admin`（RuoYi 内置，`role_id = 1`） |
| 定位 | 系统级超级用户，负责框架配置与运维 |
| 数据范围 | 不受 `paleo_admin_association` 限制 |

**可管理内容**

- RuoYi 系统管理：用户、角色、菜单、部门、字典、参数、日志
- 古生物全部业务模块（与学会总管理员相同）
- 分会管理员数据范围配置（`paleo:scope:*`）

**使用建议**

- 生产环境仅开发/运维持有，秘书处日常不使用
- 演示环境另有 `paleo_admin_demo` 角色供总管理员演示，避免依赖 `user_id = 1`

---

### 2.2 学会总管理员（秘书处）

| 属性 | 说明 |
|---|---|
| 角色标识 | `paleo_admin`（演示：`paleo_admin_demo`） |
| 定位 | 秘书处最高业务管理权限，统筹全站会员、会议、内容与统计 |
| 数据范围 | 全平台；统计页可选「全平台汇总 / 总学会 / 任一分会」 |
| 建议人数 | 秘书处 3 人可共用或按模块分岗 |

**核心职责**

#### 会员管理

- 审核入会申请书（学生会员、非学生会员均须上传，0617 已确认无豁免）
- 审核退会申请书；退会审核通过当日终止会员资格
- 审核会员费缴费凭证与发票；必要时手动驳回，允许用户重传
- 维护入会/退会申请书模板 Word
- 查看全站会员统计：总注册人数、学生/非学生会员数、非会员数、会员费累计

#### 会议管理

- 发布**总学会**学术年会、重要论坛或活动（总学会独立模块，不发布分会会议）
- 查看和管理**任意分会**会议（统筹监督，非日常运营）
- 配置单场会议四类会议费：学生会员 / 非学生会员 / 学生非会员 / 非学生非会员
- 上传盖章会议通知 PDF、摘要模板 Word（仅管理员上传，系统不自动盖章）
- 查看单次会议：报告数、住宿、野外报名、摘要打包下载
- 住宿截止后可后台代改或导入补充信息（须记录操作日志）
- 配置单场会议野外路线：名称、数量（最多 15 条，0617 已确认）

#### 报名与参会资料

- 查看全站会议报名；审核会议费凭证/发票
- 手动驳回后允许用户重新上传
- 摘要截止后可在后台代改或导入补充（须记录操作日志）
- 导出：按学会或单次会议、四类人群、凭证/发票 ZIP 打包（含 Excel 台账）

#### 内容与 CMS

- 会议通知、党务公开、重要新闻的发布、编辑、逻辑下线
- 对外展示窗口背景图上传
- 发布内容底部原文件下载链接
- 公开文件下载区：文档/影音/图片上传与管理
- 全站导航、站点级 CMS 编排（0626 CMS 动态编排 PRD）

#### 学会/分会管理

- 顶部**全平台汇总卡片**（只读总览）
- 下方 12 张可管理卡片（1 总学会 + 11 分会）：编辑、禁用/启用
- 配置分会管理员数据范围（`paleo:scope:*`）

#### 统计

- **总览 Tab**：全站汇总
- **按学会查看 Tab** 下拉顺序：
  1. 全平台汇总
  2. 中国古生物学会（总学会）
  3. 11 个专业分会
- **按会议查看 Tab**：任一会场明细
- 三层统计：全平台 / 单学会累计 / 单次会议

### 2.3 分会管理员

| 属性 | 说明 |
|---|---|
| 角色标识 | `paleo_branch_{code}`（演示：`paleo_branch_demo`） |
| 定位 | 各分会负责人，独立运营本分会的会议与内容 |
| 数据范围 | **仅绑定的 1 个分会**（`paleo_admin_association.admin_user_id → association_id`） |
| 账号规划 | **首期每分会 1 个**；数据模型支持后续多个 |

**核心职责**

| 模块 | 可做什么 | 限制 |
|------|---------|------|
| 会议管理 | 发布**本分会**学术年会；配置本分会四类会议费；上传盖章 PDF、摘要模板；配置野外路线（名称、数量，最多 15 条） | 不能发布/修改总学会或其他分会会议 |
| 报名管理 | 查看本分会会议报名；审核缴费；驳回；截止后代改摘要/住宿；导出本分会数据 | 不能看其他分会报名 |
| 内容/CMS | 发布**本分会**会议通知、文章 | 不能改全站导航；不能改其他分会/总学会内容；**党务公开、重要新闻仅总管理员可发布** |
| 公开文件 | 上传与管理本分会相关公开文件（0626 确认有权限） | 数据按分会隔离 |
| 统计分析 | 仅见**本分会**累计统计与单次会议统计 | **不能**选「全平台汇总」和其他分会 |
| 识别结果 | 复核本分会相关凭证/发票识别结果 | — |
| 学会/分会管理 | 查看/编辑**本分会**卡片 | 不能禁用其他分会；不能看全平台汇总卡片 |
| 会员管理 | 通常**只读**或查看与本分会相关用户；入会/退会审核归秘书处 | 以实际菜单分配为准 |
| 数据权限 | ❌ 无 | 不能配置他人权限 |
| 审计追溯 | 可读与本分会相关的操作日志 | — |

**本分会可管理的具体内容**

```
本分会数据（与其他学会严格隔离）
├── 会议
│   ├── 本分会学术年会发布与四类会议费配置
│   ├── 盖章会议通知 PDF、摘要模板 Word
│   ├── 野外路线配置（名称、数量，每场会议最多 15 条）
│   └── 单次会议统计（四类会议费笔数/金额、参会总人数）
├── 报名与参会资料
│   ├── 口头报告 / 展板报告数量
│   ├── 摘要 Word 集中提取（只保留最后一次）
│   ├── 住宿统计（男单间/男双/女单/女双/自主安排）
│   └── 野外报名统计（会前/会中/会后，含性别）
├── 凭证与发票
│   └── 本分会会议费凭证/发票分类导出（不与其它学会混放）
└── 内容
    ├── 本分会会议通知
    └── 本分会相关公开文件
```

**隔离规则（强制）**

- 菜单可见性：前端按 RuoYi 权限控制
- 数据安全边界：后端接口按 `paleo_admin_association` 过滤，**不可仅依赖前端隐藏**
- 不同学会的会议摘要、住宿、野外信息、凭证发票**不能混在一起**

### 2.4 财务审核员

| 属性 | 说明 |
|---|---|
| 角色标识 | `paleo_finance`（演示：`paleo_finance_demo`） |
| 定位 | 会员费/会议费凭证与发票的人工复核、统计与导出 |
| 数据范围 | 全站缴费数据（菜单受限，侧重审核） |
| 背景 | 0601 原话「财务不能进入网页系统」；系统内保留此角色供秘书处代操作或后续财务接入 |

**菜单权限（演示配置）**

| 模块 | 权限标识 | 能力 |
|------|---------|------|
| 报名管理 | `paleo:registration:list` | 查看会议报名列表 |
| 报名管理 | `paleo:registration:review` | 审核会议费凭证/发票；驳回 |
| 报名管理 | `paleo:registration:export` | 导出缴费名单、凭证 ZIP |
| 会员管理 | `paleo:membership:list` | 查看会员档案与缴费记录 |
| 会员管理 | `paleo:membership:review` | 审核会员费凭证/发票；驳回 |
| 统计分析 | `paleo:stats:list` | 查看会员费/会议费统计 |

**不能做什么**

- ❌ 发布/编辑会议、内容、CMS、公开文件
- ❌ 学会/分会管理、数据权限配置
- ❌ 入会/退会申请书审核（归秘书处总管理员）
- ❌ 代改摘要/住宿（归管理员）
- ❌ 系统用户/角色/菜单配置

**工作场景**

- 用户上传凭证/发票后，系统先走模拟智能审核自动通过；财务审核员在争议或抽查时人工复核
- 按学会或单次会议导出四类人群凭证/发票 ZIP，配合 Excel 台账对账
- 导出 ZIP 规则（0617 已确认）：三级目录结构（四类人群 → 凭证/发票子文件夹）、单包上限 1GB（超大自动分多包）、内置 Excel 汇总台账、标准化文件名（姓名_身份_日期_流水号）
- 0617：「管理员通常只在单个用户查询自己的凭证或发票信息时，才进行人工搜索核验并向用户反馈」

## 四、数据范围与隔离机制

### 4.1 数据范围判定逻辑

| 角色 | 判定方式 | 说明 |
|------|---------|------|
| 超级管理员 | `user_id = 1` 或 `admin` 角色 | RuoYi 内置 |
| 学会总管理员 | `paleo_admin` / `paleo_admin_demo` 角色 | 查库判断，不依赖 session 内 `user.roles` |
| 分会管理员 | `paleo_admin_association` 表 | `admin_user_id` 绑定 `association_id` |
| 财务审核员 | 全站（菜单受限） | 接口层不做分会过滤，或按实际配置 |

### 4.2 统计页「按学会查看」下拉规则

| 选项 | 学会总管理员 | 分会管理员 |
|------|------------|-----------|
| 全平台汇总 | ✅ 可见 | ❌ 不可见 |
| 中国古生物学会（总学会） | ✅ 可见 | ❌ 不可见 |
| 本分会 | ✅ 可见 | ✅ 可见（默认/唯一） |
| 其他分会 | ✅ 可见 | ❌ 不可见 |

### 4.3 必须隔离的数据

以下数据按学会/分会严格隔离，不可跨学会混查、混导出：

- 会议摘要 Word 文件
- 住宿信息
- 野外报名信息
- 会议费凭证与绑定发票
- 单次会议报名明细

会员费为全站统一缴纳（0612 规则：会员费只收一次），但凭证/发票仍绑定用户并按学会归档查询。

## 五、角色与关键业务流程

### 5.1 入会流程（管理员侧）

```
用户提交入会申请书
    → 学会总管理员审核（通过/驳回）
    → 用户缴纳会员费（上传凭证+发票）
    → 系统模拟智能审核自动通过 / 财务审核员人工复核
    → 会员档案激活
```

- 分会管理员**不参与**入会审核（除非另行分配 `paleo:membership:review`）

### 5.2 退会与再入会（0626 确认）

> **决策演变**：0625 客户曾倾向「已退会用户需联系秘书处，管理员后台手动批准后才能重新申请入会」；经内部评估，0626 客户最终确认退会后再入会**无需管理员解锁**，用户可直接点击「重新申请入会」进入入会流程。

```
用户提交退会申请书
    → 学会总管理员审核
    → 会员资格终止；已报名会议保留、会员价锁定
    → 用户可直接点击「重新申请入会」（无需管理员解锁）
    → 流程与首次入会相同
```

### 5.3 会议报名与缴费

```
用户确认参会 → 缴纳会议费（会员价/非会员价 × 学生/非学生）
    → 上传凭证+发票
    → 模拟智能审核 / 人工复核
    → 缴费后可下载盖章通知 PDF、摘要模板 Word
    → 提交摘要、住宿、野外报名
    → 分会管理员查看统计、导出资料
```

- 验证通过后用户不可自行修改；需管理员**手动驳回**后重传
- 摘要截止后管理员可后台代改（须记日志）

### 5.4 内容发布（0626 确认）

- **无多人审批流**：管理员直接发布
- 发布内容逻辑下线（非物理删除），保留审计
- 分会管理员可发本分站内容；全站导航仅总管理员可改

## 八、前台用户身份（非后台角色）

以下身份属于**用户前台**业务状态，与后台管理角色无关：

| 身份 | 说明 | 是否登录后台 |
|------|------|------------|
| 非会员/普通用户 | 注册账号，不缴会员费，按非会员价参会 | ❌ |
| 待审核会员 | 已提交入会申请，待管理员审核 | ❌ |
| 待缴费会员 | 入会审核通过，待缴会员费 | ❌ |
| 有效会员 | 会员费审核通过且在有效期内 | ❌ |
| 已退会 | 退会审核通过；保留分会绑定，按非会员参会 | ❌ |
| 已过期 | 超期未续费，自动变更状态（0617：视为自动退会，保留历史） | ❌ |

**预留扩展**（0612）：外籍会员、单位会员、荣誉会员——当前不影响后台角色设计，仅在会员类型字段预留扩展位。
