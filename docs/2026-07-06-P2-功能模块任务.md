# P2 — 功能模块任务

| 字段 | 内容 |
|------|------|
| 阶段 | P2 |
| 目标 | 补齐 PRD 缺失模块：识别结果、审计追溯、数据权限配置页 |
| 关联 PRD | [2026-07-05-后台管理角色说明-PRD.md](./2026-07-05-后台管理角色说明-PRD.md) §二、§三 |
| 涉及仓库 | `paleontology-cms-backend`、`paleontology-admin-latest` |
| 预估工作量 | 3–4 人日 |
| 前置依赖 | **P0 全部完成**；P1-3（数据权限页依赖绑定 API） |
| 建议顺序 | **P2-2 → P2-1 → P2-3**（审计先行，识别复核与权限变更可记日志） |

---

## 阶段目标

1. **识别结果**：对应 `paleo:recognition:*`，复核凭证/发票的智能识别（模拟 OCR）结果。
2. **审计追溯**：对应 `paleo:audit:list`，关键管理操作落库并可查询，替代仅 localStorage 计数。
3. **数据权限配置**：对应 `paleo:scope:*`，总管理员在 UI 配置管理员 ↔ 分会绑定。

## 任务清单

### P2-1 识别结果模块

**优先级**：P2  
**预估**：1–1.5 人日  
**依赖**：P0-4  
**负责模块**：backend + admin

#### 背景（PRD §2.3）

> 识别结果：复核本分会相关凭证/发票识别结果

当前系统有「模拟智能审核自动通过」逻辑，但无独立「识别结果」列表与人工复核入口。

#### 子任务

| ID | 任务 | 说明 |
|----|------|------|
| P2-1a | Flyway `V24__recognition_result.sql` | 新建 `paleo_recognition_result` 表 |
| P2-1b | 写入点 | 用户上传凭证/发票时插入；智能审核通过/驳回时更新 |
| P2-1c | `PaleoRecognitionService` + Controller | list + manualReview |
| P2-1d | 管理端页面 `/admin/recognition` | 列表 + 详情 + 复核操作 |
| P2-1e | 路由权限 | `ROUTE_PERMISSIONS` 增加项 |

#### 表结构 `paleo_recognition_result`

| 字段 | 类型 | 说明 |
|------|------|------|
| `result_id` | BIGINT PK | 自增 |
| `target_type` | VARCHAR(20) | `membership` / `conference` |
| `target_id` | BIGINT | payment_id 或 registration_id |
| `user_id` | BIGINT | 关联用户 |
| `association_id` | BIGINT NULL | 会议所属分会（会员费可为 NULL） |
| `file_role` | VARCHAR(20) | `voucher` / `invoice` |
| `file_url` | VARCHAR(500) | 文件地址 |
| `auto_status` | VARCHAR(20) | `passed` / `failed` / `pending` |
| `auto_detail` | TEXT | 识别详情 JSON（金额比对、模糊匹配等） |
| `manual_status` | VARCHAR(20) NULL | `confirmed` / `disputed` / NULL |
| `manual_comment` | VARCHAR(500) NULL | 人工备注 |
| `reviewed_by` | BIGINT NULL | 复核管理员 user_id |
| `reviewed_at` | DATETIME NULL | 复核时间 |
| `create_time` | DATETIME | 创建时间 |

#### API 设计

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| GET | `/paleo/recognition/list` | super / branch（本分会） | 分页列表，支持 status/targetType 筛选 |
| GET | `/paleo/recognition/{id}` | 同上 + 范围校验 | 详情 |
| POST | `/paleo/recognition/{id}/review` | super / branch（本分会） | `{ manualStatus, manualComment }` |

#### 管理端 UI 要点

- 列表列：用户、类型（会员费/会议费）、文件名、自动结果、人工状态、复核人、时间
- 操作：查看原文件、标记「确认无误」/「存疑」
- 分会管理员：仅本分会会议相关 + 本分会用户（按 AdminScope 过滤）
- 财务审核员：**不加**此菜单（PRD 矩阵 recognition 无财务）

#### 验收标准

- [ ] 上传凭证后可在识别结果页看到记录
- [ ] 分会管理员只见本分会数据
- [ ] 人工复核写入 `paleo_audit_log`（P2-2）
- [ ] 跨分会访问详情 API → 403

### P2-2 审计追溯模块

**优先级**：P2 / **建议最先做**  
**预估**：1–1.5 人日  
**依赖**：P0-4、P1-3  
**负责模块**：backend + admin

#### 背景（PRD §2.3、§5）

- 代改摘要/住宿须记操作日志
- 分会管理员：可读与本分会相关的操作日志
- 对应菜单 `paleo:audit:list`

当前仅有 `paleo_admin_audit_log` localStorage，Dashboard 显示今日操作数，**无独立查询页**。

#### 子任务

| ID | 任务 | 说明 |
|----|------|------|
| P2-2a | Flyway `V25__audit_log.sql` | 新建 `paleo_audit_log` 表 |
| P2-2b | `AuditLogService` | 统一写入接口 |
| P2-2c | `AuditLogAspect` 或事件监听 | 拦截关键操作 |
| P2-2d | `PaleoAuditLogController` | 分页查询 API |
| P2-2e | 管理端 `/admin/audit-trail` | 审计追溯页（只读） |
| P2-2f | 与 `/admin/audit` 区分命名 | 审核工作台=待办；审计追溯=历史 |

#### 表结构 `paleo_audit_log`

| 字段 | 类型 | 说明 |
|------|------|------|
| `log_id` | BIGINT PK | 自增 |
| `operator_id` | BIGINT | 操作管理员 |
| `operator_email` | VARCHAR(128) | 冗余便于查询 |
| `operator_role` | VARCHAR(32) | super / branch / finance |
| `action` | VARCHAR(64) | 动作编码，见下表 |
| `target_type` | VARCHAR(32) | membership / conference / cms / binding / recognition |
| `target_id` | VARCHAR(64) | 目标 ID |
| `association_id` | BIGINT NULL | 所属分会（用于范围过滤） |
| `summary` | VARCHAR(500) | 人类可读摘要 |
| `detail_json` | TEXT NULL | 变更前后快照 |
| `ip` | VARCHAR(64) NULL | 客户端 IP |
| `create_time` | DATETIME | 操作时间 |

#### 需记录的操作（action 枚举）

| action | 触发场景 |
|--------|---------|
| `MEMBERSHIP_VOUCHER_APPROVE` | 会员费凭证通过 |
| `MEMBERSHIP_VOUCHER_REJECT` | 会员费凭证驳回 |
| `MEMBERSHIP_INVOICE_APPROVE` | 会员费发票通过 |
| `MEMBERSHIP_INVOICE_REJECT` | 会员费发票驳回 |
| `JOIN_APPLICATION_APPROVE` | 入会申请通过 |
| `JOIN_APPLICATION_REJECT` | 入会申请驳回 |
| `WITHDRAW_APPLICATION_APPROVE` | 退会申请通过 |
| `WITHDRAW_APPLICATION_REJECT` | 退会申请驳回 |
| `CONFERENCE_VOUCHER_APPROVE` | 会议费凭证通过 |
| `CONFERENCE_VOUCHER_REJECT` | 会议费凭证驳回 |
| `CONFERENCE_INVOICE_APPROVE` | 会议费发票通过 |
| `CONFERENCE_INVOICE_REJECT` | 会议费发票驳回 |
| `ABSTRACT_ADMIN_EDIT` | 摘要代改 |
| `ACCOMMODATION_ADMIN_EDIT` | 住宿代改 |
| `INVOICE_DEADLINE_EXTEND` | 发票期限延长 |
| `CMS_PUBLISH` / `CMS_UNPUBLISH` | 内容发布/下线 |
| `ADMIN_BINDING_CREATE` | 管理员分会绑定 |
| `ADMIN_BINDING_REMOVE` | 管理员分会解绑 |
| `RECOGNITION_MANUAL_REVIEW` | 识别结果人工复核 |

#### API 设计

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| GET | `/paleo/audit/logs` | super：全站；branch：本分会 | 分页 + 筛选 |

**查询参数**：`pageNum`、`pageSize`、`action`、`operatorEmail`、`associationId`、`startTime`、`endTime`、`targetType`

#### 管理端 UI 要点

- 筛选：时间范围、操作类型、操作者、分会
- 表格：时间、操作者、角色、动作、摘要、目标
- 详情抽屉：展示 `detail_json`（变更前后）
- 权限：super 全站；branch 本分会；finance **不可见**

#### 验收标准

- [ ] 驳回凭证、通过入会、代改摘要等操作可在审计页查到
- [ ] 分会管理员不见其他分会日志
- [ ] 财务无法访问 `/admin/audit-trail`
- [ ] 日志写入不影响主流程性能（异步可选）

### P2-3 数据权限配置页

**优先级**：P2  
**预估**：0.5–1 人日  
**依赖**：P1-3、P2-2  
**负责模块**：`paleontology-admin-latest`（UI）+ 复用 P1-3 API

#### 背景（PRD §2.1、§7.2）

> 配置分会管理员数据范围（`paleo:scope:*`）  
> 在「数据权限」页或 `paleo_admin_association` 表中配置

当前 `BranchManagement` 是学会/分会卡片编辑，**不是**管理员绑定配置。

#### 子任务

| ID | 任务 | 说明 |
|----|------|------|
| P2-3a | 新页 `/admin/scope` | 仅 `super_admin` 可访问 |
| P2-3b | 左侧管理员列表 | 来源 `GET /paleo/admin/associations/admins` |
| P2-3c | 右侧分会绑定 | 11 分会 checkbox + 总学会说明（总学会无需绑定） |
| P2-3d | 保存 | 调 `PUT .../bindings/replace` 或 bind/unbind 组合 |
| P2-3e | 路由与菜单 | `ROUTE_PERMISSIONS`、侧栏「数据权限」入口 |
| P2-3f | 与 BranchManagement 关系 | 学会/分会管理保留；数据权限独立入口，避免混淆 |

#### 验收标准

- [ ] 总管理员可在 UI 完成绑定/解绑，无需直接改 DB
- [ ] 保存后写 `ADMIN_BINDING_*` 审计日志（P2-2）
- [ ] 目标管理员重新登录后范围立即变化（配合 P1-4）
- [ ] 分会管理员、财务访问 `/admin/scope` → 路由拦截 + API 403

## 建议实施顺序

```
P2-2（审计） → P2-1（识别） → P2-3（数据权限页）
```

| 顺序 | 原因 |
|------|------|
| 先做 P2-2 | P2-1 复核、P2-3 绑定变更都需要记审计日志 |
| 再做 P2-1 | 识别模块依赖 AdminScope + AuditLog |
| 最后 P2-3 | 纯 UI，复用 P1-3 API，依赖审计记录绑定变更 |

## 与现有页面对照

| PRD 菜单 | 现有页面 | P2 交付 |
|---------|---------|---------|
| `paleo:recognition:*` | ❌ 无 | `/admin/recognition` |

## 不在本阶段范围

- RuoYi / `sys_menu` 动态菜单（P3，已排除）

- 管理端会议/会员数据全面 API 化（独立 Phase）
- 财务识别结果只读访问（PRD 未要求，不加）
