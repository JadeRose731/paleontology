# P1 — 权限对齐任务

| 字段 | 内容 |
|------|------|
| 阶段 | P1 |
| 目标 | 财务角色菜单与 PRD 对齐；补全 `paleo_admin_association` 管理能力；前后端分会范围一致 |
| 关联 PRD | [2026-07-05-后台管理角色说明-PRD.md](./2026-07-05-后台管理角色说明-PRD.md) §二、§三、§7.3 |
| 涉及仓库 | `paleontology-cms-backend`、`paleontology-admin-latest` |

| 阻塞 | P2-3（数据权限页依赖 P1-3 API） |

---

## 阶段目标

1. 管理端菜单、路由、Tab 级权限与 PRD §三「菜单与按钮权限矩阵」一致。
2. 财务审核员：可见统计、可审缴费；**不可**入会/退会、不可 CMS/会议/分会管理。
3. `paleo_admin_association` 提供 CRUD API，支持总管理员配置「谁管哪个分会」。
4. 前端 `branchId` 与 DB 绑定同步，不以 `BUILT_IN_ADMINS` 为唯一来源。

---

## 与 PRD 权限矩阵对照（本阶段要修正的项）

| 差异点 | PRD 要求 | 当前实现 | 本阶段任务 |
|--------|---------|---------|-----------|
| 财务 → 统计分析 | ✅ 应有 | ❌ 路由未授权 | P1-1 |
| 财务 → 入会/退会审核 | ❌ 不应有 | ⚠️ 审核工作台可见 | P1-2 |
| 财务 → 业务工作台 | ❌ 不应有（`paleo:confirmed:list`） | ⚠️ 可见 dashboard | P1-1 可选收紧 |
| 数据权限配置 | `paleo:scope:*` 仅总管理员 | ❌ 无 | P1-3 API（UI 在 P2-3） |
| 分会绑定来源 | DB `paleo_admin_association` | 硬编码 `branchId` | P1-4 |

### P1-3 `paleo_admin_association` 管理 API

**优先级**：P1  
**预估**：0.5 人日  
**依赖**：P0-1、P0-3  
**负责模块**：`paleontology-cms-backend`

#### 子任务

| ID | 任务 | 说明 |
|----|------|------|
| P1-3a | `PaleoAdminAssociationService` | 绑定 CRUD + 查询 |
| P1-3b | `PaleoAdminAssociationController` | REST API |
| P1-3c | 权限 | 仅 `super_admin` 可写；`branch_admin` 可读 mine |

#### API 设计

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| GET | `/paleo/admin/associations/mine` | 已登录管理员 | 当前用户绑定的分会列表（branch_code[]） |
| GET | `/paleo/admin/associations/bindings` | `super_admin` | 全部管理员-分会绑定列表 |
| GET | `/paleo/admin/associations/admins` | `super_admin` | 管理员账号列表（含 role、email） |
| POST | `/paleo/admin/associations/bindings` | `super_admin` | 绑定 `{ adminUserId, associationId }` |
| POST | `/paleo/admin/associations/bindings/unbind` | `super_admin` | 解绑 `{ adminUserId, associationId }` |
| PUT | `/paleo/admin/associations/bindings/replace` | `super_admin` | 批量替换某管理员的全部分会绑定 |

#### 响应示例

```json
// GET /paleo/admin/associations/mine
{
  "branchCodes": ["gjzdw"],
  "associationIds": [8],
  "associationNames": ["古脊椎动物学分会"]
}
```

#### 验收标准

- [ ] 总管理员可通过 API 为任意管理员绑定/解绑分会
- [ ] 修改绑定后，该管理员重新登录，P0-4 范围立即生效
- [ ] 分会管理员调写接口 → 403
- [ ] 表结构支持「一分会多管理员」（PRD 扩展预留）
